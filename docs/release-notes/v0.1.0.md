# Release notes — v0.1.0

**First public release.** `dsh-r7-office` gives DeepSeek Harness (and any MCP
client) first-class handling of R7-Office documents: inspect, read, create,
edit, format, validate and convert `DOCX`, `XLSX`, `PPTX` and `PDF`.

> **Unofficial community project.** Not affiliated with, endorsed by or
> supported by РђРћ В«Р 7В» (R7-Office) or DeepSeek. No R7-Office code or binaries
> are redistributed; the plugin detects and drives the installation you already
> have.

## Highlights

### 18 MCP tools

One tool surface, two hosts — a native DeepSeek Harness plugin and a standalone
stdio MCP server:

`r7_inspect` В· `r7_read` В· `r7_create` В· `r7_edit` В· `r7_replace` В·
`r7_insert` В· `r7_table` В· `r7_sheet_read` В· `r7_sheet_write` В·
`r7_sheet_add` В· `r7_sheet_formula` В· `r7_slide_create` В· `r7_slide_edit` В·
`r7_convert` В· `r7_validate` В· `r7_desktop_status` В·
`r7_desktop_selection` В· `r7_desktop_exec`

### Spreadsheets and presentations are first-class

Not only DOCX. A workbook keeps **several named worksheets**, and a
presentation keeps **several slides**, through operations that edit the
package's part graph correctly rather than rewriting the document:

- `r7_create` builds every entry in `sheets[]` with its own name and data.
- `r7_sheet_add` adds a worksheet to an existing workbook, registering the
  worksheet part, its content-type override, the workbook `<sheet>` entry and
  the workbook relationship. Existing worksheets are never rewritten.
- `r7_sheet_read` / `r7_sheet_write` / `r7_sheet_formula` address a sheet by
  name or index, resolved through `xl/_rels/workbook.xml.rels` rather than
  guessed from a file number.
- `r7_slide_create` **appends** a slide to an existing deck — slide part,
  relationship part, content-type override, unique `<p:sldId>` and the
  presentation relationship — leaving the slides already present untouched.

Every one of these paths is validated end to end: the test suite asserts the
new structure, that previously existing parts were not rewritten, and that R7
itself still opens and renders the result through `x2t`.

### Non-destructive by construction

Reading a document and writing it back reproduces the file **byte for byte** —
verified against real R7 templates for all three formats. Editing one part
leaves every other package member byte-identical, so styles, themes, fonts and
numbering cannot drift. Original files are never overwritten unless you ask for
it with `outputPath`.

### Native R7 conversion

`r7_convert` shells out to the `x2t` converter of your local R7 installation
for PDF/HTML output at R7's own fidelity. R7 is auto-detected across the
standard install locations on Windows, Linux and macOS.

### Live desktop bridge

An R7-Office Desktop plugin talks back to the plugin over a loopback WebSocket,
so an agent can read the selection, modify, and save the document the user has
**open right now**.

### Security by default

Raw DocScript execution through `r7_desktop_exec` is **off by default**.
Production callers get a fixed allowlist of safe, argument-driven commands;
arbitrary code requires an explicit `developerMode: true`. The bridge binds to
`127.0.0.1` only. See [SECURITY.md](../../SECURITY.md).

## Test coverage at a glance

- **Pure unit** — ZIP reader/writer, XML helpers, R7 detection, plugin contract,
  security policy.
- **Regression** (`zip-ooxml-regression`) — real R7 templates, Unicode
  (Cyrillic/CJK/emoji, including member names), large documents (2000 members,
  4 MiB payloads, 500-paragraph DOCX), stored vs deflate, malformed packages
  (truncated, corrupt signature, corrupt payload, unsupported method,
  method mismatch, Zip64, encrypted, non-Buffer) and per-member round-trip
  fidelity.
- **File end-to-end** — the full agent workflow for all three formats, with
  "R7 really re-opens this" proven by rendering through `x2t`.
- **Desktop bridge** — the real WebSocket wire protocol, timeouts, health
  endpoint and the production security gate.
- **External client** — the shipped MCP server against a third-party SDK.

## Known limitations

- The automated **live desktop bridge test is Windows-only** (CEF DevTools
  automation against the Windows build). The bridge plugin itself is
  platform-neutral.
- `r7_convert` needs a local R7 installation; the other tools do not.
- Charts, embedded objects, SmartArt and tracked changes are preserved but not
  editable through these tools.
- File tools work on a document at rest; use the desktop bridge for a document
  the user has open.

## Installation

```bash
git clone https://github.com/OWNER/dsh-r7-office.git
cd dsh-r7-office
npm install
npm test
```

As a DeepSeek Harness plugin: install the package directory as a bundle
(`plugin_manager` → `install_bundle`). As an MCP server: point your client at
`src/mcp/cli.js` over stdio. Full instructions in [README.md](../../README.md).

## Requirements

- Node.js **>= 20** to run; **>= 22** for the full test suite.
- R7-Office Desktop **optional** — required only for PDF/HTML conversion and the
  desktop bridge.
