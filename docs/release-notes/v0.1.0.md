# Release notes — v0.1.0

**First public release.** `dsh-r7-office` gives DeepSeek Harness — and any MCP
client — first-class handling of R7-Office documents: inspect, read, create,
edit, format, validate and convert `DOCX`, `XLSX`, `PPTX` and `PDF`.

> **Unofficial community project.** Not affiliated with, endorsed by or
> supported by АО «Р7» (R7-Office) or DeepSeek. No R7-Office code or binaries
> are redistributed; the plugin detects and drives the installation you already
> have.

## Highlights

### 28 MCP tools

One tool surface, two hosts — a native DeepSeek Harness plugin and a standalone
stdio MCP server.

**Shared** — `r7_inspect`, `r7_read`, `r7_create`, `r7_convert`, `r7_validate`,
`r7_pdf_inspect`

**DOCX** — `r7_edit`, `r7_replace`, `r7_insert`, `r7_table`,
`r7_docx_formatting`, `r7_docx_sections`, `r7_docx_header_footer`,
`r7_docx_image`, `r7_docx_hyperlink`

**XLSX** — `r7_sheet_read`, `r7_sheet_write`, `r7_sheet_format`,
`r7_sheet_add`, `r7_sheet_formula`

**PPTX** — `r7_slide_read`, `r7_slide_create`, `r7_slide_format`,
`r7_slide_edit`, `r7_slide_object`

**R7 Desktop** — `r7_desktop_status`, `r7_desktop_selection`,
`r7_desktop_exec`

### Non-destructive by construction

Reading a package and writing it back reproduces the file **byte for byte** —
verified against real R7 templates for all three formats. Editing one part
leaves every other member byte-identical, so styles, themes, fonts, numbering
and media cannot drift. Original files are never overwritten unless you ask for
it with `outputPath`, and `r7_create` refuses to replace an existing document
without `overwrite: true`.

Every write is a **patch**: only the properties you name change. A gradient, a
shadow or a hyperlink an author set survives a restyle untouched.

### Read before you write

Formatting is exposed as a normalized model, not raw OOXML, so an agent can see
what it is about to change:

- **DOCX** — `r7_docx_formatting` and `r7_read({includeStyles})` report
  paragraph style, font family/size, bold, italic, underline, colour,
  alignment, indents, spacing before/after, line spacing and list/numbering.
- **XLSX** — `r7_sheet_read({includeStyles})` reports a style matrix plus merged
  ranges, row heights and column widths.
- **PPTX** — `r7_slide_read` reports every object's id, type, geometry,
  rotation, z-order, text, font, fill, stroke, alignment and paragraphs, with
  placeholder geometry and typography **resolved down the
  layout → master → `p:txStyle` chain**, so a title reports the 44 pt the
  master actually renders instead of a null.

### Spreadsheets

- `r7_sheet_format` covers font, fill, borders, alignment, wrap, number formats
  (integer, decimal, currency, percent, date, datetime, custom), merge, column
  width (including auto-fit) and row height, on a cell or a range.
- The stylesheet model parses the workbook's **own** `xl/styles.xml` and only
  ever appends. Existing font/fill/border/numFmt/cellXf indices are never
  rebuilt, because every cell refers to them by number. An untouched stylesheet
  is returned byte-identically.
- Dates are stored as real Excel serials with a date number format, **never as
  text**; numbers stay numbers under currency and percent formats.
- Worksheets are resolved through `xl/_rels/workbook.xml.rels` rather than by
  guessing that a sheet's file number matches its tab position.

### Presentations

- A deck is built on the layouts it already has. Adding a slide registers the
  slide part, its relationship part, its `[Content_Types].xml` override, its
  `<p:sldId>` entry and the presentation relationship; the master, the theme,
  the notes and every existing slide keep their original bytes.
- Slides are addressed by their **position in the deck** through
  `ppt/presentation.xml.rels`, so deleting a slide cannot silently shift a later
  target.
- Shapes, text boxes and images can be added, formatted in place, restyled,
  repositioned, reordered, duplicated and removed, each as a patch.
- SmartArt, charts, animations and transitions are **preserved, never damaged**.

### Documents

- Page size, orientation, margins, columns, page breaks and section breaks,
  written property-by-property so unnamed settings survive.
- Headers and footers, with page-number fields intact in both the
  `w:fldSimple` and the complex `fldChar`/`instrText` form.
- Images, with the aspect ratio kept, and hyperlinks, with relationships
  reused for a repeated target.
- Tables: merge/unmerge, column widths, cell shading, borders, alignment and
  row/column add and remove.
- Comments, tracked changes, footnotes, a table of contents, equations and
  embedded objects are preserved byte-identically and never edited.

### Security by default

Raw DocScript execution through `r7_desktop_exec` is **off by default**.
Production callers get a fixed allowlist of safe, argument-driven commands;
arbitrary code requires an explicit `developerMode: true`. The desktop bridge
binds to `127.0.0.1` only. See [SECURITY.md](../../SECURITY.md).

## Known limitations

- **Live desktop bridge: Windows verified.** The bridge plugin is
  platform-neutral, but the automated live test drives R7 Desktop through the
  CEF DevTools protocol and is only verified against the Windows build.
- **R7 required for PDF.** `r7_convert` needs the local `x2t` converter;
  everything else works without an installation.
- **DOCX.** Replacing or resizing an existing image, table styles, and changing
  a hyperlink's target are not implemented. Search is not revision-aware.
- **XLSX.** Conditional formatting, data validation, charts, pivot tables and
  defined names are preserved but not editable.
- **PPTX.** SmartArt, charts, animations and transitions are preserved but not
  authored; theme colours read back as tokens because no literal hex exists
  until the theme is resolved, and writes accept literals only.
- **No concurrent editing.** The file tools work on a document at rest; use the
  desktop bridge for a document the user has open.

## Installation

```bash
git clone https://github.com/OWNER/dsh-r7-office.git
cd dsh-r7-office
npm install
npm test
```

As a DeepSeek Harness plugin, install the package directory as a bundle
(`plugin_manager` → `install_bundle`). As an MCP server, point your client at
`src/mcp/cli.js` over stdio. Full instructions in [README.md](../../README.md).

## Requirements

- Node.js **>= 20** to run; **>= 22** for the full test suite.
- R7-Office Desktop **optional** — required only for PDF/HTML conversion and the
  desktop bridge.
