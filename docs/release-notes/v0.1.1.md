# Release notes — v0.1.1

**Fix CI behavior on systems without R7-Office; no functional changes.**

This is a maintenance release. Nothing about how the plugin processes documents
has changed: no engine, no tool, no conversion behaviour was touched. What
changed is the **test suite's honesty about what it needs**.

## What was wrong

v0.1.0's `npm test` only passed on a machine with R7-Office installed. On a
machine without it — including every GitHub Actions runner — it reported about
64 failures, and the README's promise that R7-dependent tests *"skip themselves
with a clear message instead of failing, so a clean machine gets a green run"*
was simply not true.

The cause was a missing distinction. A number of ordinary tests called
`engine.create(...)` and then asserted values that come from **R7's own
templates** — page size, margins, style ids, the slide-layout graph. Where R7
was installed those values were there; where it was not, the engine fell back to
the synthetic package it builds itself, the values differed, and the test failed
instead of skipping. A template had become a silent precondition of tests that
were not about templates at all.

## What changed

**The suite is now split, explicitly, in two groups:**

- **Portable tests** run on any machine with Node and must pass there. They use
  the synthetic package when no R7 template exists. This is `npm test`.
- **R7-dependent tests** — their subject is R7's own template values, the `x2t`
  converter, or the desktop editor — **skip** when R7 is absent, naming the
  reason. A run on a clean machine therefore ends green and prints how many were
  skipped.

A template can no longer be a hidden precondition of a portable test. The
decision is made in one place, `tests/helpers/r7-gate.js`, so a skip says *why*
rather than being inferred from a filename.

**A new command for the other half.** R7-dependent tests are only meaningful
where R7 is installed, so they get one:

```bash
npm run test:r7
```

It **refuses to run without an installation** rather than skipping everything
and reporting success — a run that proved nothing must not look like a pass. It
then runs the whole suite with nothing skipped, followed by the live desktop
bridge that drives the real editor over CDP and saves a document.

**`R7_OFFICE_DISABLED=1`** makes the adapter report no installation even where
one exists, so the condition CI runs under can be reproduced on a developer
machine — and so the `r7_convert` fallback paths stay covered. It short-circuits
detection; it changes no detection logic.

**CI asserts the property rather than the exit code.** The workflow now sets the
flag explicitly, and fails if the suite did not run (a floor on the number that
passed), if anything failed, or if the skip count is missing from the summary.

## Verification

| Check | Result |
|---|---|
| `npm test` without R7 (`R7_OFFICE_DISABLED=1`) | **486 tests, 397 pass, 0 fail, 89 skipped** |
| `npm test` with R7 installed | **486 tests, 485 pass, 0 fail, 1 skipped** — that one skip is an opt-in fixture the caller supplies |
| `npm run test:r7` | **PASS** — full suite with nothing skipped, plus the live desktop editor |
| GitHub Actions, Ubuntu / macOS / Windows × Node 22 and 24 | **PASS** |

A test file that depended on the host rather than on R7 was also found and
fixed: `tests/unit/adapter-pdf.test.js` compared font-list candidates against
hard-coded `C:\...` strings while the code builds them with the host's path
module, so it could never pass on Linux or macOS. That failure had nothing to do
with R7 and would not have been caught by changing only whether R7 is present.

## Upgrading

No action required. Behaviour is unchanged; only the test suite and the
documentation of how to run it differ from v0.1.0.

## Known limitations

Unchanged from [v0.1.0](https://github.com/blazar-source/dsh-r7-office/releases/tag/v0.1.0),
including the cosmetic thin line that R7's PDF converter can draw through an
italic `Subtitle` paragraph, and the visual-acceptance caveat that a PDF may
carry correct text while rendering incorrectly.

One thing this release makes explicit rather than leaves implicit: the
**containers the engines build when no R7 template is available are minimal**.
They have always been so, and no functionality changed here, but the new tests
pin exactly where the boundary lies — a document or deck created without R7 is
editable, but it does not carry R7's styles or its slide-layout graph:

- The synthetic DOCX has no `word/styles.xml`, so styles the engine names —
  `Heading1`, `ListParagraph`, and `Hyperlink` — are referenced without being
  defined. A link created without R7 is therefore not rendered as a link.
- The synthetic PPTX has no slide layout, master or theme, so `addSlide()` on a
  layout is refused with *"No slide layout available in this presentation. Pass
  `baseSlideIndex` to clone an existing slide."* The only way to add a slide
  without R7 is to clone an existing one.

Both are reported by the suites added in this release, so a future fix has
somewhere to land.
